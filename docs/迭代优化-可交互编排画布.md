# 迭代优化：可交互编排画布

本轮迭代对应需求「设计规格 → PM 任务分解 → 编排 → 可交互可视化」（m00665 / m00691），
补齐 ORCH-01 里最薄弱的一环：计划图从「CSS 网格 + SVG 折线」升级为可拖拽、可连线的 React Flow 画布，
坐标与依赖边都能落到服务端。

## 1. 交付内容

### 1.1 后端：坐标与依赖边可写

| 变更 | 位置 |
| --- | --- |
| `Plan.layout_json`（`{task_uid: {x, y}}`） | `backend/app/db/models.py` |
| 幂等补列（`node_attempts.heartbeat_at`、`plans.layout_json`） | `backend/app/db/base.py` `_ensure_columns()` |
| `PlanLayout` / `PlanDep` 请求体 | `backend/app/api/schemas.py` |
| `find_cycle()` 公共环检测 | `backend/app/engine/planner.py` |
| `PATCH /plans/{id}/layout` | `backend/app/api/plans.py` |
| `POST /plans/{id}/deps`、`DELETE /plans/{id}/deps` | 同上 |
| 用例 `test_plan_canvas_layout_and_dependency_edges` | `backend/tests/test_plans_api.py` |

约定：

- 坐标只接受有限浮点，保留 1 位小数；未知 uid 也不会报错，前端按任务集合过滤；
- 新增依赖的语义是「`source` 是 `target` 的前置」，与 `PlanTask.deps_json` 一致；
- 自依赖 400 `self_dependency`、端点缺失 404 `task_not_found`、重复 409 `dependency_exists`、
  成环 400 `dependency_cycle`（`details.cycle` 返回具体路径），已提交/归档计划 400 `plan_locked`；
- 任何一次依赖编辑都会把计划打回 `editing`，前端随后 400ms 防抖重新 `validate`，波次、关键路径随之更新。

> 迁移坑：SQLite 单连接池（`pool_size=1`）下，`_ensure_columns()` 必须先用 inspector 把列读完，
> 再进入 `engine.begin()`；否则在事务里再拿连接会自锁到 `pool_timeout`（60s）。

### 1.2 前端：React Flow 画布

`frontend/src/canvas/PlanGraph.tsx` 重写（约 410 行），API 保持受控：

```ts
<PlanGraph
  tasks={tasks} snapshot={snapshot} layout={layout} selected={uid}
  onSelect={...} onMoveNodes={...} onAddDep={...} onRemoveDep={...} />
```

- **节点**：任务卡（角色色条、UID、effort/点数、两行标题、角色/优先级/依赖数），
  `CRIT` 角标标关键路径，`ERR` 角标标校验错误；
- **泳道**：每个波次一条虚线泳道（`WAVE 01 · N TASKS`），`pointer-events: none` 不挡拖拽；
- **连线四态**：关键路径（墨色 2.4px）、跨角色交接（灰虚线）、校验错误（红色点线）、普通依赖（浅灰 1.3px）；
  边 hover 变粗墨线；
- **交互**：节点可拖，落点汇总所有任务坐标交给页面防抖落库；右侧 source 手柄拖到目标左侧 target 手柄新增依赖；
  点击连线弹确认后删除依赖；MiniMap 按角色着色，Controls 缩放/适配；
- **取景**：只在任务集合或波次数变化时 `fitView`，校验刷新不会重置视野；「重置布局」清空本地坐标并回写空对象。

`frontend/src/pages/PlanPage.tsx` 负责乐观更新与持久化：

- `moveNodes`：先 `setQueryData` 改本地 `plan.layout`，700ms 防抖 `PATCH /layout`，失败提示但不回滚；
- `addDependency` / `removeDependency`：成功后 invalidate `plan`/`plans` 并触发 `validate`；
- `planLayout` 用 `useMemo` 固定引用——内联 `?? {}` 会让画布的重建 effect 每帧触发。

样式追加在 `frontend/src/styles/plan.css` 末尾（`.plan-flow-wrap` / `.flow-lane` / `.flow-task` / `.flow-handle` /
`.flow-toolbar`），延续纸白 `#F4F4F2`、墨 `#161616`、信号黄 `#FFFA00` 与切角按钮的既有视觉。

手工验收：

1. 打开任一有效计划，图视图应显示泳道 + 任务卡 + 四种连线；
2. 拖动两个节点后刷新页面，位置保持；
3. 从 `T1` 右侧手柄拖到 `T3` 左侧，依赖数 +1，波次/关键路径自动重算；
4. 点击该连线删除依赖，指标回到原状；
5. 制造一个环（如 `T1→T3` 且已有 `T3→T1` 路径），页面提示 `dependency_cycle` 并高亮相关节点。

## 3. 已知边界

- 坐标按 plan 持久化，但不进 `PlanSnapshot`：恢复历史版本只恢复任务/依赖，不恢复画布位置；
- 连线交互依赖鼠标手柄，触屏尚未适配；
- 波次泳道按快照计算，依赖编辑后的 400ms 窗口内泳道仍是旧值；
- 覆盖率按 `design_section` 字符串匹配统计，同一章节的多个合并标题只算一次。

# 增量 2：设计覆盖率

目标：把「PM 是否真的按设计规格分解」变成可看见、可路由的信号，而不是只看任务数量。

## 4. 交付内容

### 4.1 后端

| 变更 | 位置 |
| --- | --- |
| `build_coverage(tasks, sections)` | `backend/app/engine/planner.py` |
| `_coverage_warnings(coverage)` | 同上 |
| `snapshot.coverage` + `validation.warnings` | `validate_plan()` 成功路径 |
| `PlanSnapshot.coverage_json` | `backend/app/db/models.py` |
| 幂等补列 `plan_snapshots.coverage_json` | `backend/app/db/base.py` |
| `coverage` / `warnings` 出现在 validate 响应与快照 | `backend/app/api/plans.py` |
| PM 提示词「每章至少一条任务承接」+ 编号章节索引 | `backend/app/engine/plan_generation.py` |

结构：

```json
{"total": 10, "covered": 8, "ratio": 0.8,
 "sections": [{"title": "1 目标与范围", "key": "目标与范围", "level": 1, "line": 1, "tasks": ["T1"]}],
 "uncovered": ["9 数据导出", "10 附录"],
 "orphan_tasks": ["T9"]}
```

警告码（`warnings`，不阻断提交）：

- `section_uncovered`（最多 12 条，`details.section` 带章节名）；
- `section_uncovered_more`（还有多少章未覆盖）；
- `section_orphan_tasks`（`design_section` 匹配不到任何章节的任务，最多 6 个 uid）。

### 4.2 前端

- `PlanSnapshot.coverage`、`PlanValidation.warnings` 类型；顶部指标条新增 `COVERAGE 8/10 章`；
- 画布上方「设计覆盖 / COVERAGE」条：每章一个 chip，显示承接任务数；未覆盖章节黄黑斜纹 + `—`；
- 点击 chip 聚焦该章节的任务（`focusUids`），再点一次取消；未覆盖章节点击给出提示；
- 选中节点时画布自动高亮祖先/后代链路，链路外节点与连线降到 30% / 16% 透明度；
- 聚焦优先于选中链路：点章节时只看该章节的任务，取消聚焦后回到选中链路模式。
