# 运行图与节点检查器交互设计（RUN-GRAPH-UI-01）

> 版本 v1.0 · 日期 2026-11-22 · 状态：已实现（待合入） · 基线：`main@d83331a` · 对应分支：`feat/node-interaction`
> 交付物：公共模块 `frontend/src/canvas/graphLayout.ts`、面板 `frontend/src/panels/NodeInspector.tsx`，以及
> `RunPage.tsx` / `ExecutionMap.tsx` / `PlanGraph.tsx` 接线。不包含 xyflow 运行图画布（F10）、坐标持久化、Twin 双图。

## 1 目标与现状

### 1.1 目标

把运行页的执行图从「只能点开一次性只读抽屉」升级为**可观察 → 可操作 → 可追溯**的三层交互，并把运行图与计划图
重复的血缘/门阻挡/相位分列逻辑抽成共享纯函数模块（任务书 B 级要求：共享逻辑优先抽到 `canvas/graphLayout.ts`，
旧组件改为调用共享函数，见 `docs/tasks/orchestration-workbench.md:160`）。

### 1.2 现状与缺口

- 改造前点节点只打开一次性的只读抽屉：手工 `fetch` 详情、无选中态、无实时刷新、无上下游/动作（本轮已用
  `NodeInspector` + react-query 替换，见 `RunPage.tsx:143-154` 的 `["node", runId, selectedNodeId]` 查询）。
- 计划图的选中血缘早已实现（`README.md:172`「选中节点会高亮它的祖先/后代链路，其余节点退到背景」），但运行图没有；
  运行图与计划图的图逻辑各写一份（`docs/迭代优化-可交互编排画布.md:129-130` 描述的 30% / 16% 暗化只存在于计划图）。
- 死代码遗留：`frontend/src/canvas/FlowCanvas.tsx:1-121`（旧版 xyflow 运行图）全前端无引用，本轮不删除、不复用。
- SSE 事件是**逐个命名注册**的白名单（`client.ts:226-233`），后端新增事件不登记则前端静默收不到；节点详情此前无法
  按节点精准刷新。

### 1.3 本轮交付的两层（L3 画布为可选）

| 层 | 能力 | 状态 |
|---|---|---|
| L1 观察层（必做） | 节点选中 + 血缘高亮 + 8 区块检查器 + 事件驱动实时刷新 | 已实现 |
| L2 操作层（必做核心） | 重试（可带反馈）/ 重置 / 跳过 / 注入反馈 + 二次确认 + 幂等保护 | 已实现 |
| L3 画布层（可选） | `graphLayout.ts` 抽公共并三处复用；xyflow `RunGraph` 视图 | 模块已实现；`RunGraph` 未做（默认保留 DOM 网格） |

## 2 信息架构

| 层 | 入口 | 用户动作 | 数据来源 |
|---|---|---|---|
| L1 观察 | 执行图节点、运行账本行、检查器上下游链接 | 点节点选中/取消；再点同一节点或 Esc 关闭；点图内空白取消 | `snapshot.nodes`（即时）+ `GET /nodes/{id}`（详情）+ `snapshot.artifacts` |
| L2 操作 | 检查器底部动作条 | 重试（弹窗填反馈、可勾选级联重置）/ 重置（二次确认）/ 跳过（弹窗风险提示 + 原因）/ 注入反馈 | 动作端点 + `can_*` 显隐；动作成功后 invalidate 快照/指标/节点详情 |
| L3 画布 | 执行图容器（默认网格） | 缩放/MiniMap/双图切换（未做） | `graphLayout` 纯函数；xyflow 只在计划图 |

信息架构原则：**观察不改变状态，操作必须二次确认，画布是观察的增强而不是替代**——L3 未做时不牺牲 L1/L2，
运行页默认观感与旧版一致（B 级门槛：旧页面功能与观感不得退化）。

### 3.2 调用方改造（公共模块成立的证据）

- `ExecutionMap.tsx`：删除本地 `isDone()`、`held` BFS、`columns`、`numbers` 四份实现，改 import 共享函数（`ExecutionMap.tsx:5`）。
- `RunPage.tsx`：删除本地 `heldKeys()`，改用 `graphLayout` 版本（`RunPage.tsx:13`、`:231-234`）。
- `PlanGraph.tsx`：血缘 `active` memo 改用 `collectLineageByKey(selected, tasks, task => task.task_uid)`（`PlanGraph.tsx:238-244`），
  行为不变：聚焦优先于选中链路，选中不存在时返回空集。

### 3.3 为什么只抽纯函数、不抽 DOM 测量

- 测量层依赖 `getBoundingClientRect()` / `ResizeObserver`（`ExecutionMap.tsx:68-112`），是运行图 DOM 网格专属；
  计划图是 xyflow 坐标系，两套技术强行合并会把公共模块变成最小公分母（执行方案列为高风险项）。
- 纯函数不依赖 React/DOM，可在无前端测试栈的前提下用 typecheck + 人工验收守护；抽取范围以「键 → 集合」为主，
  两类画布都能复用。
- 只抽被至少一处真实调用的函数为公共契约；`buildChildren` 等预留导出不强行接线，避免为复用而改无关调用点。

## 5 NodeInspector 信息分区

### 5.1 props

契约 props 为 `{ runId, runStatus, node, detail?, events, open, onClose, onAction }`（`NodeInspector.tsx:27-48`）；实现另外提供
`detailError?`（详情请求失败文案）、`onSelectNode? / onFilterEvents? / onOpenArtifact? / artifacts? / eventText?`，
用于错误占位、上下游跳转、事件过滤、复用工件编辑 Modal 与统一事件文案。

### 5.2 八个区块

| # | 区块 | 内容 | 数据来源 | 空态 |
|---|---|---|---|---|
| 1 | 基础信息 | node_key / 类型 / 状态 / 相位 / 波次 / 序号 / 尝试 n/max / 运行状态 / 依赖 / open_gate / assignee | 详情 | `—` / 「无依赖」「无」 |
| 2 | 上下游 | `upstream[]`、`downstream[]`（名字 + key + 状态，可点击跳转选中） | 详情 | 「起始节点，无上游」/「末端节点，无下游」 |
| 3 | 执行参数 | `config` 中非保护键（instruction/artifact/timeout_s…）只读展示 | 详情 `config` | 「无执行参数」 |
| 4 | 调度状态 | `PROTECTED_CONFIG_KEYS`（feedback/retry_at/retry_count/escalation/round/review…）灰显只读 | 详情 `config` | 「无调度状态」 |
| 5 | 尝试记录 | attempts 表（#/状态/MODEL/起止/TOKEN/ERROR）+ 每条 error 原文 | 详情 `attempts` | 「尚无尝试记录」 |
| 6 | 最近消息 | 默认折叠 3 条、可展开全部（单条截断 2000 字） | 详情 `messages` | 「暂无消息」 |
| 7 | 节点事件 | 详情 `events` 与实时 SSE 事件按 `seq` 去重合并、升序；默认 8 条可展开 30 条；「只看此节点事件」 | 详情 + `events` prop | 「暂无该节点事件」 |
| 8 | 产出工件 | `snapshot.artifacts` 中 `created_by_node === node_key` 的项，点击打开现有工件编辑 Modal | `snapshot.artifacts` + 详情 `artifact_kinds` | 「暂无该节点产出的工件」，另提示「计划产出」 |

八个区块位于 `NodeInspector.tsx:263-514`，面板 header/底部动作条属于 chrome、不计入 8 区块；`artifact_kinds` 只用于
「计划产出但尚未写入」提示（`NodeInspector.tsx:483-514`）。面板状态：未选中显示 `Empty`（`:235-238`）；详情未返回时显示
`Spin`；详情请求失败显示 `Alert`「节点详情读取失败」+ `detailError` 文案（`:250-260`、`RunPage.tsx:721`）。

**数据源注意**：`snapshot.nodes[].attempts` 是数字（次数），不能当 `NodeDetail.attempts[]` 使用；详情一律走
`GET /nodes/{id}`（`types.ts:63-93`）。节点事件由详情历史与实时 SSE 按 `seq` 去重合并（`NodeInspector.tsx:147-162`），
执行参数/调度状态按 `PROTECTED_CONFIG_KEYS` 分组（`:164-172`）。

## 6 动作条与二次确认

动作条只按后端 `can_retry / can_reset / can_skip / can_feedback` 显隐（`NodeInspector.tsx:515-544`），前端不自己推导矩阵；
四个 `can_*` 全为 false 时显示提示语（终态 run / 运行中 / 有待裁决门 / 其他，`NodeInspector.tsx:174-181`）。

- **重试**：弹窗可填反馈（可选，≤4000 字）+ 勾选「级联重置下游（下游回到 pending，避免旧工件污染）」，默认不勾选；
  成功后节点回 pending、attempt+1（`NodeInspector.tsx:557-574`）。
- **重置**：黄色 Alert 说明「重置会清理调度状态，节点回到 pending」+ 默认开启的级联重置下游勾选（`:575-590`）。
- **跳过**：必须显示风险提示原文「该节点不产出工件，下游将按缺失输入继续」，可填跳过原因，确认按钮为危险色（`:591-607`）。
- **注入反馈**：必填 1–4000 字，`showCount`；文案明确「不会触发重跑；下一次 attempt 生效」（`:608-620`）。
- **幂等保护**：提交时把当前详情 `status` 作为 `expected_status` 传给后端（`NodeInspector.tsx:206`），状态已变化时后端返回
  409 `status_conflict`，弹窗保留、显示 `ApiError.message`（`:210-212`），由用户刷新后重试。
- 成功后：`messageApi.success` 关闭弹窗，`RunPage.runNodeAction` 统一 invalidate `["snapshot"]`/`["metrics"]`/`["node", runId, nodeId]`
  （`RunPage.tsx:300-332`）；SSE 事件到达后还会精准刷新一次。

## 7 实时性

`RunPage` 的 SSE 回调按四类分流（`RunPage.tsx:175-209`）：

| 事件类别 | 处理 |
|---|---|
| 终态事件 `run_finished/run_error/run_stopped` | 若当前有选中节点，先 invalidate 该节点详情，再全量 invalidate snapshot/metrics/review；`client.ts:241-243` 关闭 EventSource |
| `node_token` | 只进入事件日志，不触发任何查询刷新 |
| 选中节点的事件（`event.node_id === selectedNodeId`） | 只 invalidate `["node", runId, selectedNodeId]`，不刷新全页 |
| 其他结构事件 | invalidate snapshot/metrics/review，保持运行账本与门面板实时 |

- 查询 key 精确到 nodeId（`RunPage.tsx:143-154`）是「精准 invalidate」的前提，避免一次事件刷新所有节点查询造成风暴。
- 兜底轮询：节点详情在 `pending/running/waiting_human` 时 8s 轮询、终态后停止（`RunPage.tsx:148-153`），用于 SSE 不可用
  （断网/代理缓冲）时的最终一致。
- 事件日志侧：`seen` 集合按 `seq` 去重，保留最近 400 条（`RunPage.tsx:175-186`）；事件抽屉支持 `filterNodeId`
  过滤，`node_id` 渲染为 `node_key`（`:364-374`、`:688-714`）。

## 9 与计划图的复用关系

- **同一套血缘算法**：计划图用 `collectLineageByKey(selected, tasks, task => task.task_uid)`（`PlanGraph.tsx:238-244`），
  运行图用 `collectLineage(selected, nodes)`（`ExecutionMap.tsx:49-52`），二者共享 `graphLayout.ts:32-72` 的实现；
  差异只在键（`task_uid` vs `node_key`）与画布技术（xyflow vs CSS Grid + SVG）。
- **不同画布技术**：计划图是 `@xyflow/react` 画布（可拖拽/连线），运行图是自研 DOM 网格 + 绝对定位 SVG（`ExecutionMap.tsx:157-208`），
  因此只共享纯函数、不共享渲染层。
- **计划图回归要求**：焦点优先级不变（章节聚焦 `focusUids` 优先于选中链路，`PlanGraph.tsx:238-240`）；四视图
  （任务详情/流程监控/活动/执行图）拖拽、改名、依赖增删、撤销、全览、聚焦行为不变；`npm run typecheck` 通过；
  附前后截图。B 级门槛见 `docs/tasks/orchestration-workbench.md:113-119`。

## 10 验收与已知边界

手工验收（10 条，交付给「用例准备与实际测试」同学）：

1. 启动 Mock（`scripts/e2e_demo.py --auto --demo-reject`）后打开 `/runs`，进入一个运行中的 run；
2. 点执行图节点：节点出现黄底选中框，祖先/后代保持、旁支变暗；右侧检查器 8 区块有数据；
3. 再点同一节点取消选中；点图内空白取消；`Esc` 关闭且输入框内不误触；
4. 检查器里点上下游节点可跳转选中；点「产出工件」打开现有工件编辑 Modal；
5. 运行中等待 5–10 秒：检查器/事件不经手动刷新自动更新；
6. 失败或升级节点：填反馈重试 → attempt+1、状态推进；重复点击不产生重复事件；
7. 勾选「级联重置下游」重试 → 下游节点回到 pending；
8. `pending` 节点跳过 → skipped，下游继续跑；HUMAN_GATE 节点无跳过按钮（后端 400 保护）；
9. 事件抽屉按节点过滤，`node_id` 显示为 `node_key`；4 个新事件文案可读；
10. 回归：计划页四视图交互正常；`npm run typecheck` 通过；后端 `pytest` 全绿。

已知边界与取舍：

- **无前端测试栈**：不引入 vitest（避免 lock 膨胀与构建时间），以「纯函数抽离 + typecheck + 手工验收」守护；
  `graphLayout.ts` 的纯函数是未来补单测的最低成本入口。
- **未做 xyflow 运行图（F10）**：设计规格 L354 的 M1「xyflow 只读画布 + MiniMap」留待后续；本轮默认保留现有网格图，
  避免 B 级改动演变成整体重写。
- **节点详情请求失败**：显示 `Alert` 错误占位（`detailError`，`NodeInspector.tsx:250-260`），v1 只提供文案、不提供
  面板内重试按钮；切换节点或刷新页面即可恢复（已记入后续）。
- **未做深链**：选中态不写入 URL，刷新页面回到未选中；`?node=<node_key>` 深链留待后续。
- **触屏/窄屏**：执行图仍是横向列布局，选中依赖点击；触屏适配未验证（与计划图画布一致）。
- **构建验证**：本轮 `npm run typecheck` 通过（`tsc --noEmit`，2026-11-22 实测）；`npm run build` 产物证据由 PR 证据包回填。
