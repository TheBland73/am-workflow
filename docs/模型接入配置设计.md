# 模型接入配置设计（Models Pool）

> 状态：v0.1。上游：[设计规格说明书](./设计规格说明书.md) §5.4；本文为其模型层的单独详设。
> 目标口径：**产品内用户可自定义配置**供应商、base_url、api_key、**API 接口协议**、上下文窗口等全部配置项；理论上广泛支持各类模型与 API；**不假设本地部署大模型**（协议上兼容远程 Ollama 等自建端点，但产品不内置模型）。

---

## 1 目标与原则

1. **零硬编码供应商**：任何供应商/中转/自建网关都通过"配置"接入，不改代码。
2. **协议即插件**：接口协议（请求/响应/流式/工具调用的线格式）是 Provider 的一个可配置属性，适配器按协议分发；新增协议=新增一个 Adapter 类。
3. **能力显式声明**：上下文窗口、是否支持工具调用/结构化输出/视觉，由用户在模型条目上声明，编排与记忆模块按能力降级。
4. **一切可记账**：每次调用回填 tokens/费用到 node_attempts，支撑成本面板与预算熔断。
5. **密钥安全**：加密落盘、界面脱敏、日志与工件强制脱敏。

## 2 概念模型：Provider → Model → Binding 三层

```
Provider（供应商连接：怎么连）
  └─ Model（模型条目：调什么、能力如何）
       └─ Binding（绑定：谁在用——角色模板默认 / 任务级覆盖 / 分级路由）
```

- Provider 回答"endpoint+鉴权+协议"；Model 回答"这个端点下的具体模型与其能力参数"；Binding 由角色模板与任务分解器消费。

## 3 Provider 配置字段（`provider_configs`）

| 字段 | 类型 | 说明 |
|---|---|---|
| name | str | 用户可读名（如"DeepSeek 官方"） |
| **protocol** | enum | `openai_chat`（OpenAI Chat Completions 兼容——覆盖绝大多数供应商）/ `anthropic_messages` / `gemini_generate` / `custom`（预留） |
| base_url | str | 端点根（不含路径的由适配器拼接） |
| api_key_enc | bytes | Fernet 加密存储；任何响应/日志只出脱敏形式 |
| extra_headers | json | 兼容中转站所需的自定义头（如 OpenRouter 的 attribution） |
| timeout_s / max_concurrency | int | 超时与该 Provider 的并发上限 |
| enabled | bool | 停用的 Provider 其模型不可被绑定 |

## 4 协议适配层

**Adapter 统一接口**（后端内部格式与线格式解耦；各协议线格式细节以官方文档为准，链接见 §13）：

```python
class ProtocolAdapter(Protocol):
    async def chat(self, messages: list[Message], tools: list[Tool] | None,
                   params: GenParams) -> Message: ...
    def stream(self, messages, tools, params) -> AsyncIterator[StreamEvent]:  # text_delta / tool_call_delta / usage / done
    async def count_tokens_estimate(self, messages) -> int:        # 估算（字符/4 兜底）
```

| 协议 | 路径惯例 | 鉴权 | 流式格式 | 工具调用 | 用量字段 |
|---|---|---|---|---|---|
| `openai_chat` | `POST {base}/chat/completions` | `Authorization: Bearer` | SSE `data: {choices:[{delta}]}`；**流式记账需请求带 `stream_options:{"include_usage":true}`，仅末 chunk 含 usage；不支持该参数的网关降级为字符估算** | `tools`/`tool_calls`（OpenAI function calling 格式） | `usage.prompt_tokens/completion_tokens` |
| `anthropic_messages` | `POST {base}/v1/messages` | `x-api-key` + `anthropic-version` | SSE `content_block_delta` | `tools`/`tool_use` content block | `usage.input_tokens/output_tokens` |
| `gemini_generate` | `POST {base}/v1beta/models/{m}:generateContent` (streamGenerateContent) | `?key=` 或 `x-goog-api-key` 头 | `candidates[].content.parts` 增量 | `functionDeclarations`/`functionCall` | `usageMetadata` |
| `custom` | — | — | — | — | 预留：脚本化模板（M2 后再议） |

工具调用与消息在内部统一为 `Message / ToolCall{id,name,args} / ToolResult{id,output}` 三种归一结构；各适配器负责与线格式互转（映射表见 §7）。

**重试基线**：M0/W1 适配器内置 1 次指数退避重试（429/5xx/网络错误），现场演示不至于一次抖动即 node_failed；M1 起参数化（次数/退避基数可配）。

## 5 Model 条目字段（`model_entries`）

| 字段 | 说明 |
|---|---|
| model_name | 协议侧真实模型名（如 `glm-4.7`、`deepseek-flash`——**以供应商当前模型列表为准**，历史名可能已映射退役） |
| display_name | UI 名 |
| **context_window** | 用户声明（tokens）；上下文预算的依据 |
| max_output_tokens | 单次输出上限 |
| cap_tools / cap_json / cap_vision | 能力标记：工具调用 / JSON 结构化输出 / 图像输入 |
| price_in / price_out | 每百万 tokens 单价（可选，记账用） |
| enabled | — |

## 6 上下文窗口管理

**预算分配**（构造 prompt 时按序预留，由编排核执行）：

| 区 | 预算（占 context_window） | 内容 |
|---|---|---|
| 系统提示 | ~5% | 角色模板+纪律 |
| 记忆注入 | ~10% | L3 全文（小）+ L1 摘要 |
| 工件引用 | ~25% | 上游工件（优先引用+章节摘要，超预算降级为引用） |
| 对话/工具历史 | ~30% | 逐条保留，最旧的先压缩 |
| **输出预留** | max_output_tokens | 硬预留 |

（五区合计约 70%，**剩余约 30% 留作工具结果与压缩缓冲**。）

**超窗策略（按序）**：① 工具结果截断（保留头尾+退出码）；② 对话历史最旧段摘要压缩；③ 工件正文降级为"引用+要点"；④ 仍超窗→报错转人工（不静默丢内容）。跨 attempt 长任务遵循基线原则：**检查早期约束是否仍在上下文**，关键约束在系统提示区重复注入。

## 7 工具调用跨协议归一

| 线格式（openai_chat） | 内部归一 | 降级路径 |
|---|---|---|
| `tool_calls:[{id,function:{name,arguments}}]` | ToolCall | — |
| role=tool 的 `tool_call_id` 消息 | ToolResult | — |
| `response_format=json_object` | 结构化输出 | — |
| （模型不支持工具时） | 提示词协议：把工具清单写进系统提示，要求输出 JSON `{"tool":"…","args":{…}}`，运行时解析执行 | cap_tools=false 的模型自动启用 |

## 8 绑定与分级路由

- 角色模板 `default_model_id` 为默认绑定；任务分解器可为单个任务覆盖（task.assignee.model_id）。
- **分级建议**（配置页可改）：抽取/判决/校验 → 小模型；讨论/开发 → 中档；方案/终审评审 → 强档。与调研结论一致：写入记忆的判决类调用用中价位模型即可，重活（合并/重写）才用强模型。
- cap 缺失时自动降级（§7），降级行为写入 node_log（界面如实标注；程序/小模型/Agent 各管各的）。

## 9 密钥与安全

- api_key 用 [Fernet](https://cryptography.io/en/latest/fernet/)（密钥文件 `<data>/secret.key`，首启生成）加密落盘；GET 响应只回 `sk-****abcd` 形式。密钥文件不入仓库：支持 `AM_SECRET_KEY` 环境变量注入；**换机迁移=同时拷贝 DB 与 secret.key**（README 注明）。
- 日志、node_log、messages trace、工件正文统一过脱敏过滤器（正则匹配 sk- / Bearer / api-key 模式）。
- 测试连接请求不打业务流量：不带模型时仅 `GET /models` 类轻调用，带模型时发 1 轮 8-token 对话并回传延迟/回复。
- 模型发现：`GET /providers/{id}/models` 拉取供应商可选模型（`openai_chat` 的 `GET /models`）；
  `POST /providers/{id}/models/import` 批量写入本地模型表，已存在的同名模型跳过；预设创建供应商时自动补建内置模型。

## 10 配置 UI 规格

- Providers 页：卡片列表（名称/协议/端点/状态）→ 新建/编辑抽屉：Preset 下拉自动填 base_url+protocol → 用户补 api_key → 保存。
- 校验：base_url URL 格式；protocol 必选；context_window ≥ 8192；超时 1–300s。
- **测试连接**按钮：有本地模型时带模型真发一句，显示往返延迟与回复；失败显示可读错误（401=密钥错误/404=路径不对/超时）。
- **拉取模型**：供应商展开区请求远程列表，勾选导入；已存在的置灰跳过。
- Models 页：表格（模型名/窗口/能力标记/价格/启停）→ 行内编辑；绑定预览（哪些角色/任务在用）。

## 11 与其他模块的接口

| 调用方 | 接口 | 说明 |
|---|---|---|
| Agent 运行时 | `pool.adapter_for(model_id).stream/chat(...)` | 统一归一结构（§4） |
| 编排核 | `pool.account(attempt_id, usage)` | 记账 → node_attempts；预算熔断回调 |
| MemoryService | `pool.estimate_tokens(text)` / 判决模型调用 | 注入预算与写入判决用小模型 |
| 前端 | /providers /models 全套 REST | §10 |
