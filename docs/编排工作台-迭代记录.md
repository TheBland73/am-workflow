# 编排工作台 · 5 轮迭代记录（ORCH-01）

> 接续 [`迭代优化-可交互编排画布.md`](迭代优化-可交互编排画布.md) 的增量 1（React Flow 画布）与增量 2（设计覆盖），
> 本文记录增量 3–7：R1 正确性、R2 视觉语义、R3 可编辑、R4 提交运行、R5 生成链路。
>
> 目标：把「设计规格 → PM 提议 → 程序校验/编波 → 可拖拽可编辑画布 → 提交运行」这条链路做顺、做美、做得能改。
>
> 起点是一个子智能体审计：输入、PM 生成、校验、图渲染、提交运行逐段读代码，产出 40 余条问题与 5 轮改造建议；随后按 R1→R5 逐轮实现，每轮都做 typecheck / build / 截图或接口实测。

## R1 正确性：让页面先「有内容、看得清」

| 问题 | 处理 |
| --- | --- |
| `plan_token` 发 `{text}`、页面读 `payload.token`，PM 流永远空白 | 发送端同时带 `text`/`token`，接收端 `payload.text ?? payload.token` |
| 422/400 的结构化 `detail` 被 `JSON.stringify` 塞进 toast | `client.ts` 统一取 `detail.message`，其余情况回退字符串 |
| React Flow 容器高度 0，画布整块空白 | React Flow 根节点自带内联 `height:100%`，普通选择器压不过；改用 `.plan-flow-wrap .react-flow{position:absolute!important;inset:0!important}`，壳层给 `clamp(600px, calc(100vh - 300px), 880px)` |
| 三栏栅格第三列被详情抽屉占位，画布仅 594px | 详情是 `position:fixed` 抽屉，栅格改两栏 `286px minmax(0,1fr)` |
| 自动 `fitView` 把 5 列压到 0.32，字号视觉 4–5px | 取消自动适配，默认 `zoom:0.68`；工具条「全览」按需 fitView |
| 7–9px 的导航/标签/图例遍地 | 统一抬到 11–15px，卡片正文 12.5px |

## R2 视觉语义：一张图看懂「谁做什么、卡在哪」

- 角色色带：开发 `#1D4ED8`、测试 `#0F766E`、设计 `#7C3AED`、PM `#B45309`、评审 `#BE123C`、运维 `#15803D`。
- 卡片：`T1 · W1 · M · 2PT` 头，标题下补 2 行描述（取 description，空则 acceptance[0]），底部角色 chip / 章节 / 依赖数 / 优先级，左上 6px 色带，右上 CRIT 角标。
- 连线：普通依赖实线、关键路径加粗、跨角色交接虚线、校验错误红色虚线；图例补齐四种线型 + 角色色条。
- 泳道按波次分层，泳道头与卡片左缘对齐；选中节点高亮祖先/后代，其余降到 50% 透明度。
- 小地图缩到 138×92，不再压住右下角卡片。

## R3 可编辑：改名、草稿、回滚

- 双击卡片改名：6–40 字校验，`PATCH /plans/{id}/tasks/{uid}`，成功后 400ms 防抖重新校验。
- 右栏草稿按 `task_uid` 记忆：切换节点不再丢未保存内容；顶部「未保存」斜纹标签 + 「放弃修改」。
- 快照历史弹窗：每次校验生成一个版本，列版本/任务数/波数/校验结果/时间，可恢复；「当前」版本禁用。
  - 语义澄清：后端 `is_valid` 表示「是否当前有效版本」，历史版本显示「历史」而不是「无效」；恢复后前端自动再校验一次。
- 画布工具条：全览、重置布局、历史、任务详情；提示文案移到图例左侧。

## R4 提交运行：让计划真的被执行

- `PlanCommit` 支持 `budget_tokens`（10,000–20,000,000，越界 400 `budget`），提交弹窗加预算输入，事实行实时更新。
- 节点 config 从 3 个字段补到 `task_uid/task_title/design_section/role_key/description/effort/priority`。
- `_run_dev` 按任务角色选模型（`pool.pick_role_model(role)`，未绑定回退 `dev`），prompt 增加「角色」「任务说明」，并按角色追加意图（测试/设计/PM/评审/运维）；不再是所有任务都当开发。
- `Run.idea_text` 改为「编排工作台 <plan>：<产品>（N 个任务 / M 波）」。

## R5 生成链路：长文档与可见的流

- 设计规格 ≤16,000 字全文进入 prompt；超长时保留开头 62% + 结尾 38%，中段标注省略字数——避免「后半章没有任务」。
- 章节索引带编号与总数，PM 更容易按章节对齐；`max_tokens` 从 4096 提到 `min(model.max_output_tokens, 6000)`。
- 生成过程顶部固定 `PM STREAM` 面板：实时 token、字数、进度条、自动滚到底；流结束后可从「设计来源」看 `raw_output`。
- 长文 brief 的单元测试覆盖 30 章文档：断言索引、省略标记、末章标题与首尾正文都在。

## 已知边界

- 图布局按波次固定分列，任务很多时（>8 波）需要「全览」或横向滚动；暂不支持自由泳道折叠。
- 快照按版本全量存任务 JSON，未做 diff 视图。
- 提交运行生成的是 `dev_*` 节点前缀（历史命名），角色信息在 config 与 prompt 中生效，节点 key 未改。
- 计划生成仍是「一次流式输出 + 失败修复一次」，没有多轮对话式补任务。
